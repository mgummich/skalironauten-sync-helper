Skalironauten Sync Helper

Das Daily Standup in unter einer Minute.

Aktionstag lesen, Mood Check machen, Bild in den Team-Chat kopieren. Lokal im Browser, ohne Account, ohne Backend — React 19, Vite 8, Tailwind v4.

Kein Backend React 19 + Vite 8 Tailwind v4 930 Aktionstage 273 Mood-Bilder Nur im Browser

01Überblick

Der Sync Helper ist ein Begleiter für das tägliche Standup eines kleinen Dev-Teams. Er hat genau eine Aufgabe und erledigt sie um 09:00 Uhr in unter einer Minute:

  1. Aktionstag — der kuriose Gedenktag des Tages aus einer Liste mit 930 Einträgen, mit Kategorie, Region, Beschreibung und Wikipedia-Link.
  2. Mood Check — ein zufälliges Meme-Raster (3×3), eine Zahl von 1 bis 9. Öffnet sich nie von allein.
  3. Teilen — Bild kopieren oder Herunterladen bringt das Mood-Bild in den Team-Chat.

Dazu kommen zwei weitere Tabs: der Kalender über 2026/2027 — welcher Tag ist Arbeitstag, welcher der erste Arbeitstag der Woche, wie viele Aktionstage liegen darauf — und die Moods-Galerie mit allen Stimmungsbildern, inklusive eigener Uploads.

Bewusst nicht enthalten: Accounts, Server, Team-Ansicht, Synchronisierung zwischen Geräten. Alle Daten bleiben im Browser des Nutzers.

02Bedienung

Diese Seite ist der schnellste Weg hinein: Sie beschreibt jeden Tab so, wie man ihn im Standup benutzt. Ein Konto braucht es nicht — die App aufrufen genügt.

Der übliche Ablauf am Morgen: App öffnen › Aktionstag lesen › Mood Check starten › Zahl wählen › Stimmung speichern › Bild kopieren › in den Team-Chat einfügen. Zusammen unter einer Minute.

Tab „Heute“

  1. Datum wählen — die Pfeile links und rechts springen einen Tag vor oder zurück, Zu heute kommt zurück zum aktuellen Tag. Die Badges darunter sagen, ob der Tag ein Arbeitstag ist und ob er der erste Arbeitstag der Woche oder des Monats ist.
  2. Aktionstag lesen — die große Karte zeigt den Gedenktag des Tages mit Kategorie, Region, Beschreibung und Wikipedia-Link. Hat ein Tag mehrere, blättert der Stepper (1 / 3) durch sie; auf dem Desktop stehen alle rechts als Liste.
  3. Mood Check machen — Mood Check starten öffnet ein zufälliges 3×3-Meme-Raster. Feld 1–9 antippen, dann Stimmung N speichern. Das Antippen allein speichert nichts, und der Dialog öffnet sich nie von selbst. Passt das Bild nicht, zieht Zufällig wählen ein neues; ein bestimmtes Bild wählt man im Moods-Tab. Gespeichertes lässt sich über Ändern jederzeit überschreiben.
  4. Teilen — Bild kopieren legt das Bild als PNG in die Zwischenablage (wo der Browser das nicht kann, wird stattdessen heruntergeladen); Herunterladen speichert die Originaldatei. Der Button bestätigt zwei Sekunden lang.

Tab „Kalender“

  • Mobil ein Monat pro Bildschirm, auf dem Desktop alle zwölf Monate eines Jahres nebeneinander; oben rechts lässt sich zwischen 2026 und 2027 umschalten.
  • Jede Zelle zeigt die Zahl der Aktionstage an diesem Tag und einen bernsteinfarbenen Punkt, wenn es der erste Arbeitstag der Woche ist. Wochenenden und bundesweite Feiertage sind grau, heute hat einen dunklen Rahmen.
  • Filter — Suche nach Namen, Kategorie-Chips und ein Regions-Picker mit Type-ahead (227 Regionen). Die Filter wirken auch auf die Zähler in den Zellen.
  • Ein Tag antippen öffnet seine Liste; Im Standup anzeigen springt mit genau diesem Eintrag zurück in die Heute-Ansicht.

Tab „Moods“

  • Alle Stimmungsbilder alphabetisch, gefiltert nach Alle, Ungenutzt, Genutzt und Eigene — jeweils mit Anzahl.
  • Ein Bild antippen zeigt es groß, mit allen Tagen, an denen es schon einmal gewählt wurde. War es das bereits, weist ein bernsteinfarbener Hinweis darauf hin — verboten ist es nicht. Für heute wählen setzt es als Bild des heutigen Mood Checks und öffnet diesen direkt.
  • Hochladen fügt ein eigenes Bild hinzu: Datei wählen, Titel bzw. Frage eintragen, optional eine Quelle. Empfohlen sind 3×3-Raster, 1000–2400 px breit. Das Bild bleibt auf diesem Gerät und wird nirgendwohin übertragen.

Tastatur und Barrierefreiheit

  • Tab läuft durch alle Bedienelemente, jedes zeigt einen sichtbaren Fokusring.
  • In der 1–9-Auswahl bewegen die Pfeiltasten die Auswahl, Esc schließt jeden Dialog, und der Fokus kehrt danach zum auslösenden Button zurück.
  • Wer Systemanimationen reduziert hat, bekommt die Oberfläche ohne Übergänge.

Wo liegen meine Daten? Ausschließlich im Browser dieses Geräts — es gibt keinen Server und keine Synchronisierung. Auf der öffentlichen Pages-Version verschwindet alles mit dem Schließen des Tabs; lokal bleibt es erhalten. Ein anderer Browser oder ein anderes Gerät sieht deshalb nichts von den eigenen Stimmungen.

03Schnellstart

Ab hier geht es um die Entwicklung. Vorausgesetzt wird Node 24 — dieselbe Version, mit der CI und die Pages-Bereitstellung bauen. 

# Abhängigkeiten installieren
npm install

# Dev-Server auf http://localhost:3000
npm run dev

# Produktions-Build nach dist/ (tsc + vite build)
npm run build

# Build lokal prüfen
npm run preview

npm test führt die Vitest-Suite aus. Getestet ist die reine Logik in src/modules/data/: die Feiertags- und Arbeitstagsregeln in dateUtils.ts und die Regionsnormalisierung in normalizeRegion.ts. Komponententests gibt es bewusst keine.

Im Dev-Build sitzt oben eine schmale DEV-Leiste: Sie springt auf ein beliebiges Datum und leert den lokalen Speicher — praktisch, um den ersten Arbeitstag der Woche oder einen leeren Zustand nachzustellen.

04Architektur

Der Code ist in fünf isolierte Subsysteme unter src/modules/ geschnitten. Abhängigkeiten laufen nur in eine Richtung: ui → daily/calendar/mood → data. Die Datenschicht kennt keine Komponenten.

data/ Datenschicht

Reine Logik, keine React-Abhängigkeit.

  • dataLoader.ts — importiert aktionstage.json und baut den Index nach Monat/Tag, ohne die Quelldaten zu verändern.
  • dateUtils.ts — Arbeitstag = Mo–Fr minus bundesweite Feiertage (Ostern wird berechnet), erster Arbeitstag der Woche / des Monats.
  • normalizeRegion.ts — normalisiert die gescrapten Regionsnamen (227 Werte).
  • storage.ts — einziger Ort, an dem Storage-Keys entstehen; räumt beim Start die Keys der entfernten Standup-Notizen ab.

mood/ Stimmungsbilder

Mitgelieferte Bilder aus mood-scales/ plus eigene Uploads.

  • moodManifest.ts — findet die Assets per import.meta.glob und verknüpft sie mit den Metadaten aus mood-scales.json (Titel, Kategorie, Maße); Vite hasht die Bilder in den Build.
  • moodLibrary.ts — führt mitgelieferte und hochgeladene Bilder zu einer Liste zusammen und leitet die Nutzung aus den mood:*-Einträgen ab, statt sie doppelt zu speichern.
  • moodBlobs.ts — winziger IndexedDB-Wrapper; nur die Blobs der Uploads liegen dort, die Metadaten im normalen Store.
  • moodManager.ts — zieht ein Bild pro Dialog-Öffnung, bevorzugt ungenutzte und meidet die letzten fünf; hält den Zug pro Tag fest, damit Karten-Thumbnail und Dialog übereinstimmen.
  • MoodsView.tsx, MoodDetailSheet.tsx, MoodUploadSheet.tsx — Galerie, Detailansicht mit Nutzungen, Upload.

daily/ Heute-Ansicht

Die primäre Ansicht.

  • DailyView.tsx — Datumszeile mit Badges, Aktionstag- und Mood-Karte.
  • AktionstagCard.tsx — Hero-Karte mit Stepper; Desktop zeigt alle Einträge des Tages als Liste.
  • MoodCheckModal.tsx — Bild, 1–9-Auswahl, Zufällig wählen, Herunterladen, Bild kopieren, Speichern. Auswahl allein speichert nie.

calendar/ Kalender

Ein Monat pro Bildschirm (mobil), 12 Monate (Desktop).

  • CalendarView.tsx — Suche, Kategorie-Chips, Jahr-Umschalter.
  • MonthGrid.tsx — Montag-first-Raster; Zähler pro Zelle respektieren die Filter.
  • RegionPicker.tsx — Combobox mit Type-ahead für 227 Regionen.
  • DayDetailModal.tsx — übergibt Datum + Eintragsindex an die Heute-Ansicht.

ui/ Shell

Layout im Bahn-Look (v4).

  • AppShell.tsx — Routing-State zwischen Heute, Kalender und Moods.
  • Header.tsx — weiße App-Leiste mit rotem Markenzeichen, Desktop-Tabs mit roter Unterkante, mobile Bottom-Tabs mit roter Oberkante.
  • cls.ts — die geteilten Klassenbausteine: Pill-Buttons, gefüllte Felder, Karten, Fokusring.
  • Sheet.tsx — natives <dialog>: Bottom-Sheet mobil, zentrierter Dialog auf dem Desktop.
  • Lightbox.tsx — Vollbild-Ansicht eines Mood-Bildes.
  • DevToolbar.tsx — nur in Dev-Builds.

Assets

Bleiben im Projekt-Root.

  • aktionstage.json — 930 Einträge: Name, Datumsregel, Kategorie (4), Region (227), Beschreibung, Wikipedia-URL.
  • mood-scales/ — 273 Meme-Raster als WebP (mood-001.webp … mood-273.webp), bis 1200px breit. mood-scales.json beschreibt jedes Bild: id, file, title, category, Abmessungen und den früheren Dateinamen für die Migration. Die id ist die stabile Identität im Speicher.

Datenfluss

aktionstage.json› dataLoader (Index nach Monat/Tag)› entriesForDate(date, filters)
Systemdatum› dateUtils (Feiertage, Ostern)› isWorkday · isFirstWorkdayOfWeek/Month
mood-scales/*› moodManifest› moodManager (Ziehung, letzte 5 meiden)› MoodCheckModal
Upload› IndexedDB (Blob)+ storage (Metadaten)› moodLibrary
DailyView› storage.ts› localStorage

05Daten & Persistenz

Der gesamte Zustand liegt im Browser. Alle Keys entstehen in storage.ts, und dieselbe Datei wählt auch den Speicher: localStorage lokal, sessionStorage in öffentlichen Builds mit VITE_EPHEMERAL_STORAGE=true — dort ist nach dem Schließen des Tabs nichts mehr da.

Wie oft ein Mood-Bild verwendet wurde, wird nie gespeichert, sondern beim Rendern aus den vorhandenen mood:*-Einträgen abgeleitet. So kann kein zweiter Zähler auseinanderlaufen. Keys der früheren Standup-Notizen (notes:*) werden beim Start gelöscht.

KeyTypBeschreibungFallback
mood:{YYYY-MM-DD} { value, imageId, savedAt } Gespeicherter Mood Check, value von 1 bis 9. —
moodDraw:{YYYY-MM-DD} string Gezogenes Bild für einen noch nicht gespeicherten Check, damit Thumbnail und Dialog gleich sind. Wird beim Speichern gelöscht. bei Bedarf gezogen
moodRecent string[] Die letzten fünf gezogenen Bild-IDs; neue Ziehungen meiden sie. []
moodPick:{YYYY-MM-DD} string In der Galerie für diesen Tag gewähltes Bild; hat Vorrang vor der Zufallsziehung. —
moodImages { id, title, sourceUrl?, width, height, addedAt }[] Metadaten der selbst hochgeladenen Bilder. Die Bilddaten selbst liegen als Blob in IndexedDB (sync-helper/moodBlobs), verknüpft über die id. []
ui { lastRoute, calendarMonth, filters } Letzter Tab (Heute, Kalender oder Moods), angezeigter Kalendermonat, aktive Filter (q, category, region). Defaults

Arbeitstag-Regeln

  • Arbeitstag = Montag bis Freitag, abzüglich bundesweiter Feiertage.
  • Feiertage 2026: 01.01, 03.04, 06.04, 01.05, 14.05, 25.05, 03.10, 25.12, 26.12 — 2027 wird über das Osterdatum berechnet.
  • Erster Arbeitstag der Woche = Arbeitstag, bei dem alle früheren Tage Mo…(d−1) derselben ISO-Woche Wochenende oder Feiertag sind.

06Design-System

Bahn-inspirierte Signaletik, bewusst nicht „App-Store“: flache weiße Flächen auf kühlem Grau, Haarlinien, enge Radien, tabellarische Ziffern. Keine Verläufe, keine Illustrationen, keine Emoji als Icons.

Die Farbkomposition (v4) ist die eigentliche Regel: rund 60 % der Fläche ist slate-100, etwa 30 % Weiß (App-Leiste, Karten, Bottom-Bar), der Text slate-900 — und unter 3 % Rot. Rot erscheint pro Screen höchstens viermal: Markenzeichen, eine gefüllte Aktion, die aktive Tab-Markierung, rote Outline-Buttons und Links. Die App-Leiste ist weiß mit einer slate-200-Haarlinie — nie ein roter Header.

Buttons

Alles Pillen. Primär: gefülltes red-600. Sekundär: weiß mit 1,5 px red-700-Rand. Tertiär: slate-400-Rand. Icon-Buttons sind 44 px-Kreise.

Felder

Gefüllt in slate-100, oben abgerundet, mit einer einzigen 2 px starken Unterkante (slate-500), die im Fokus auf red-600 wechselt.

Karten

Randlos weiß mit 0 2px 8px rgba(0,0,0,.08); was noch auf den Nutzer wartet, bekommt .12. Listen trennen Haarlinien statt Kästen.

Typografie, Abstände, Bewegung

Schrift

Source Sans 3, Gewichte 400/500/600/700. 44px Hero (Desktop), 30px Datum, 22px Dialogtitel, 18px Kartentitel, 16px Fließtext — 14px Minimum. Zeilenhöhe 1,5 im Text, 1,1–1,2 in Titeln.

Raster

4px-Basis: 8 / 12 / 16 / 24 / 32. Seitenrand 16 mobil, 32 Desktop. Radien: Karten 8, Buttons und Chips voll, Felder oben 4.

Bewegung

150 ms für Stepper und Auswahl, 200 ms für Dialoge und Copy-Erfolg, 2 s Haltezeit. Keine Endlos-Animationen. motion-reduce setzt alle Dauern auf 0.

Barrierefreiheit ist Teil des Designs: Touch-Ziele ≥ 44×44 px mobil, sichtbarer Fokusring auf jedem interaktiven Element, role="dialog" mit Fokus-Falle und Escape, aria-live="polite" für Statusmeldungen. Kein Kontrast unter 4,5:1.

Die vollständige Vorlage liegt als statische Artboards im Repository unter design_handoff_sync_helper/. Verbindlich ist v4 (Bahn-Komposition); v3, v2 und das dunkle v1 sind nur noch Referenz. Der Handoff-Text daneben beschreibt jeden Screen inklusive Zuständen und Texten.

07Deployment

Die App ist ein rein statisches Bundle — kein Server, keine API, keine Umgebungsvariablen. Sie läuft überall, wo sich Dateien ausliefern lassen.

GitHub Pages

.github/workflows/pages.yml baut bei jedem Push auf main und veröffentlicht: die App unter der Wurzel der Pages-URL, diese Dokumentation unter /docs/. Einmalig in den Repository-Einstellungen unter Settings → Pages → Source „GitHub Actions“ auswählen.

In vite.config.ts steht base: './', damit die Asset-Pfade relativ bleiben und der Build sowohl unter user.github.io/repo/ als auch unter einer eigenen Domain funktioniert.

Sicherheit & Privatsphäre

  • Keine Drittanfragen: die Schrift (Source Sans 3, OFL) liegt selbst gehostet unter public/fonts/ — die App lädt nichts von fremden Servern.
  • Content-Security-Policy: Produktions-Builds bekommen per Vite-Plugin ein CSP-Meta-Tag (default-src 'self'; img-src zusätzlich blob: für hochgeladene Bilder). Der Dev-Server lässt es weg, weil HMR Inline-Skripte braucht.
  • Dependabot hält npm-Pakete und die auf Commit-Hashes gepinnten GitHub Actions wöchentlich aktuell — npm gebündelt in einem Sammel-PR.

Öffentliche Builds speichern nur für die Sitzung. Der Pages-Workflow baut mit VITE_EPHEMERAL_STORAGE=true; dann liegt der gesamte Zustand in sessionStorage statt localStorage und ist mit dem Schließen des Tabs weg. Lokale Builds behalten localStorage.

Unabhängig davon gilt: Auf GitHub Pages ist der ausgelieferte Inhalt öffentlich — auch aktionstage.json und die Bilder in mood-scales/. Stimmungen verlassen den Browser aber nie.
